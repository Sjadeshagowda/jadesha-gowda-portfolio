Overview

A smart tourist safety platform designed to improve tourist protection through real-time monitoring, emergency response, and AI-assisted threat detection. Engineered as a final-year team project by a team of 4 engineering students.

Technologies

React Native React TypeScript Node.js Express.js Python FastAPI MongoDB Socket.IO TensorFlow YAMNet Leaflet GeoJSON Twilio

Key Features

  • GPS-based live location tracking: Continuous telemetry streaming to administrative dispatch.
  • GeoJSON-based geofencing: Automated boundary violation alerts when approaching hazardous perimeters.
  • AI-powered scream detection: Acoustic signal analysis leveraging YAMNet and TensorFlow.
  • Safe-word recognition: Natural language trigger classification for covert distress calls.
  • NLP-based threat classification: Emergency priority assessment from transcript feeds.
  • Offline SOS queue & SMS alerts: Twilio SMS fallback when high-speed internet data is disconnected.
  • Real-time communication: Bidirectional Socket.IO live updates between tourist app and police portal.
  • Police and administrator dashboard: Interactive dashboard utilizing React and Leaflet.
  • Incident reporting and safety monitoring: Structured incident logging and audit trails.

Development & Deployment Scope

Academic capstone engineering project prototype. Features and workflows operate in verified test/development environments and are not claimed as production-deployed emergency public services.

Web & Java • REST Architecture

EV Charging Slot Booking System In Development

Project Overview

A backend-focused application designed to manage EV charging station slots and booking workflows, reducing wait times and optimizing charging point utilization.

Booking Workflow

  1. Driver inspects station availability and connector types (CCS, Type 2, CHAdeMO).
  2. System verifies real-time calendar and returns open charging time slots.
  3. Driver reserves a specific slot window, creating a confirmed booking record.
  4. Cancellation and slot release workflows manage dynamic reallocation.

REST API Structure (Proposed Design)

  • GET /api/v1/stations — Query all charging stations.
  • GET /api/v1/stations/{id}/slots — Inspect slot availability for a given station.
  • POST /api/v1/bookings — Create a slot reservation.
  • PUT /api/v1/bookings/{id}/cancel — Cancel booking and release slot allocation.

Database Design & Entities

Relational entities include ChargingStation (1 : N) → ChargingSlot (1 : N) → BookingRecord, linked with User entities via Spring Data JPA mappings in MySQL.

Technology Stack

Java 21 Spring Boot Maven Spring Data JPA MySQL Lombok REST APIs

Phishing Detection Tool

Event & Venue Details

Developed during the CyberSecure '25 Hackathon on 20 May 2025 at the IPCC Lab, BITM.

Description & Scanning Mechanism

A keyword-based phishing detection tool that scans URLs or text payloads and classifies results into four distinct states:

Phishing: High-risk keywords, known phishing brand spoofs, or suspicious TLD patterns confirmed.
Possibly Phishing: Partial anomalies or redirection tokens flagged, requiring user vigilance.
Safe: Standard syntax conforming to clean domain registries with zero suspicious signatures detected.
Invalid: Malformed URL syntax, empty strings, or unparseable text format.
